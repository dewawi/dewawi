# D4B1 synthetic thermal coupling and exchanger contracts

Baseline: local D4A commit `113a6bc5` (`add multi-circuit compressor stage evaluation`). This change provides a deliberately limited, synthetic thermal solver. It does not calculate or release real-machine performance, add public selection, Inquiry/Sales/PDF integration, hydraulics, heat recovery or heating. Every result remains `eligible=false`.

## Closed, versioned data contracts

The existing `technicaldataset` table already stores a versioned discriminator, canonical payload and SHA-256. No SQL change or new table is necessary. Two registered dataset types are added, both with `schema_version=1` and internal `contract_version=1`:

| Type / reference | Contract |
|---|---|
| `heat_exchanger_map` / existing `component_spec.data.specification.thermal_map_ref` | Component key/model/role/construction, refrigerant, saturation definition, physical section identities/isolation, permitted media and explicit constant properties, function identifier, variables/units, input/output/flow limits, fan conditions, pressure-drop evidence and known restrictions/gaps. |
| `thermal_balance_model` / optional `machine_configuration.data.thermal_model_ref` | Exact circuit key, explicit idealized compressor heat-balance boundary, Te/Tc search intervals and bounded numerical settings. |

Existing configuration topology, instances, profiles, stage definitions and graph identities remain authoritative. No parallel machine configuration is introduced. The optional reference stays absent when not supplied, preserving old normalized records/hashes. Existing immutable revisions, including approved packages, are not rewritten. Old D2B/D3/D4A imports and results remain compatible.

Every new record retains the common D2B key/revision, source filename/SHA-256/locator, manufacturer name/version, owner, missing-data blockers and canonical payload hash. A component profile pins the article and exact component-spec revision; that spec pins its map revision. Import and evaluation check component/model/role/refrigerant, construction and section identity against the map. The thermal model's circuit must exist in the stored machine. New and old references enter the same owner-scoped, pinned graph.

Only `usage=synthetic_test_only` is accepted. Registered functions are:

- `synthetic_evaporator_effectiveness_v1`;
- `synthetic_air_condenser_effectiveness_v1`;
- `synthetic_water_condenser_effectiveness_v1`;
- medium properties: `synthetic_constant_cp_density_v1`;
- energy balance: `synthetic_hermetic_no_external_losses_v1`.

No imported formula is evaluated. Unknown models, units, fields, versions or interpolation procedures are rejected. Interpolation is explicitly `none_analytic`. Future real OEM curves require their own reviewed registered contracts; they cannot masquerade as these synthetic models.

The exchanger contract specifies variables `saturation_temperature`, `secondary_inlet`, `secondary_outlet` in degC, `volume_flow` in m3/h, `heat_flow` in kW and `pressure_drop` in kPa. Each physical section has its own key, effectiveness strictly between zero and one, saturation/inlet/outlet/flow ranges and nullable constant synthetic pressure drop. Several sections require `refrigerant_sections_are_isolated=true`. They can be imported and bound structurally; the D4B1 solver explicitly blocks multisection coupling.

Each permitted medium identifies composition, phase (`single_phase_liquid` or `dry_gas`), density in kg/m3, cp in kJ/(kg K), property-temperature range and source locator. Density/cp may be null in a draft and then block mathematical calculation. No water, glycol or air property is inferred. All sources are covered by the map's source revision/hash and payload hash. Air maps require dry-gas media and separate fan execution/speed conditions; liquid maps reject fan conditions. Missing fan evidence blocks calculation, and an explicit mismatch is unsuitable. No fan power or system air distribution is estimated.

Complete synthetic JSON is generated by `tests/items/fixtures/thermal-circuit.php`; it uses only free, synthetic fixtures and the existing D4A topology factory.

## Mathematical boundary and functions

For each section, with explicitly supplied volumetric flow V, density rho, cp and effectiveness epsilon:

- `mass_flow_kg_s = rho * V_m3_h / 3600`;
- `C_kW_K = mass_flow_kg_s * cp_kJ_kg_K`;
- fixed prepared conductance `K_kW_K = epsilon * C_kW_K`;
- evaporator: `Qe_kW = Ke * (secondary_inlet_degC - Te_degC)`, outlet = inlet - Qe/Ce;
- condenser: `Qc_kW = Kc * (Tc_degC - secondary_inlet_degC)`, outlet = inlet + Qc/Cc.

This is a registered constant-effectiveness synthetic sensible-stream model with isothermal refrigerant, not an OEM heat-exchanger law. Air and water have separate registered roles, media, volumetric flows, fluid states, fan requirements and map domains. Equal numerical results in the reference cases follow from explicitly chosen equal capacity rates, not from a shared ambient-temperature default. Conditions and property ranges are checked at both inlet and calculated outlet. Heat direction must be positive. Flow, saturation and secondary-temperature bounds use exact decimal comparisons; a value infinitesimally outside a range is not rounded inside.

The idealized balance explicitly declares all compressor electrical input transferred to the refrigerant, zero external motor/casing heat loss, zero transient storage and zero other heat input. All four declarations are required; contradictory fractions/losses are rejected using exact canonical decimals. Only within this synthetic boundary is `required_condenser_heat = compressor_Q + compressor_P` evaluated. It is not a confirmed real condenser rating. Real-machine loss models, pump heat and auxiliaries remain unavailable.

Residuals are explicitly:

`r_e(Te,Tc) = sum_D3_Q(Te,Tc) - Qe(Te)`

`r_c(Te,Tc) = sum_D3_Q(Te,Tc) + sum_D3_P(Te,Tc) - Qc(Tc)`.

## Private service and result contract

```php
$result = $technicalData->evaluateThermalCircuit(
    $machineDatasetId,

    $expectedPayloadSha256,
    $request,
    'synthetic_reference' // default: 'technical', which cannot emit a synthetic solution

```

Example air request (no default values are inserted):

```json
{
  "stage_key": "full",
  "operating_mode": "cooling",
  "evaporator": {
    "medium_key": "fixture:liquid", "inlet_degC": "10",

```

A water condenser instead uses an explicitly identified source-liquid medium, its inlet/flow/state, its own registered map and no air/fan fields. The source-water passage is represented in the existing machine hydraulic-loop structure.

Optional `compressor_contexts` retains D4A/D3's full per-active-instance context and exact matching rules. Optional `temperature_offset_probe` requires its model identifier plus explicit ambient/supply temperatures, condensing offset, evaporator approach and water spread. It emits only an isolated, flagged diagnostic Te/Tc pair, never a solver input or seed. It is forbidden for water condensers. Stored approximation parameters never become implicit defaults. The example probe's hypothetical supply10/Te5 is separate from the actual HX inlet10/outlet7.5 in the reference request above.

`Items_Service_ThermalCircuit::evaluate(machine, request, resolver, compressorCallback, calculationBlocker)` is the independently testable mathematical interface. Both callbacks must refer to the same authorized, validated, pinned snapshot. They are not alternative authorization entry points. `HeatExchangerMap::prepare/atPoint` provides the closed synthetic map evaluator. D4A `MachineStage::evaluate` calls the shared D3 evaluation for each active instance at every trial point. Inactive instances do not contribute. Direct compressor-polynomial profiles and indirect component-spec polynomial references are supported.

The service shares the existing D4A graph snapshot, hash/header/profile/article/variant checks and approval-chain verification. D3's pinned record preparation is separated privately from its existing point evaluation and cached only within this single transaction. Iterations do not repeatedly query/revalidate the same immutable package, while all point/context/envelope/numeric checks remain active. Public D3/D4A interfaces are unchanged. The existing exact decimal comparator is reused through TechnicalJson by D3 and the new range checks.

Result version one includes:

- calculation version `synthetic_single_circuit_nested_bisection_v1`, `scope=synthetic_thermal_coupling_only`, mode/status/blockers and `eligible=false`;
- copied original request, stored mode/stage, exact machine article/revision and all dataset/profile hashes, lifecycle states, source records and approval/withdrawal evidence;
- thermal model version/balance boundary/numerical settings and actual exchanger instances, profile/map revisions, sections, normalized media/flow/fan conditions;
- uniqueness certificate, convergence/iteration/evaluation counts, bounded outer trace and both final Te/Tc search intervals;
- on convergence only: solved Te/Tc, complete original D4A instance/circuit/stage result, both synthetic exchanger results/outlets/approaches, Q/P/required heat, both residuals, outward residual enclosures and propagated numerical temperature-error bounds;
- explicit unavailable useful-machine capacity and machine efficiency. D4A's original engineering blockers remain in its nested compressor-only result; root blockers explain that convergence is synthetic and actual machine/expansion/control/pressure-loss/auxiliary evidence is missing.

Nonconvergence, ambiguous roots, missing operands or uncertain numerical precision leave `solution=null`. Trial points can appear only in the clearly identified convergence trace. There is no hidden fallback to the last point and no persistent run-table write.

## Solver, limits and numerical verification

Search bounds come from the exact thermal-model revision, must satisfy Te_max<Tc_min and remain within both concrete exchanger maps and confirmed compressor operating regions. D4B1 conservatively requires simple rectangular compressor envelopes with confirmed corner inclusion. Other envelope geometries produce a blocker; D3's broader standalone polygon support is preserved. Every actual point still passes D3's own region check. No extrapolation is performed.

Before iteration, outward-rounded binary64 intervals of the actual D3 cubic polynomials/derivatives over the search rectangle establish:

1. `F_Te = Q_Te + Ke > 0`, so the evaporator residual has at most one Te root at fixed Tc;
2. signs of both full lower/upper Te edges bracket that root for every Tc;
3. a constant nonzero sign for the coupled Jacobian determinant:
   `(Q_Tc + P_Tc - Kc) * (Q_Te + Ke) - (Q_Te + P_Te) * Q_Tc`.

Consequently the outer condenser residual along the evaporator root is strictly monotone. Failure to establish these conditions yields `solution_uniqueness_not_proven` or an explicit missing-bracket blocker, not a guessed root. A two-root quadratic fixture and a degenerate continuum fixture are rejected before iteration. This is a certificate for the documented polynomial/constant-slope synthetic model, not a proof of real-machine physical uniqueness.

Nested bisection solves Te at each Tc, then Tc. Fixture settings are absolute heat tolerance **1e-7 kW**, Te/Tc interval width **1e-8 K**, maximum **60 inner and 60 outer iterations**. The closed contract accepts 1..80 iterations per level and tolerances from 1e-9 to 1e-3; invalid budgets/tolerances are rejected. At most `(outer_limit + 2) * inner_limit` stage evaluations occur (6,560 at the contract's maximum), each evaluating only its actual active instances. IEEE-754 powers/products and fixed-order D3/D4A sums are retained. No intermediate display rounding is used.

Each trial also computes outward polynomial/heat-residual enclosures. Uncertainty is propagated through lower bounds on the certified inner/outer slopes. Arithmetic uncertainty exceeding one quarter of the heat or temperature tolerance blocks the run with `thermal_arithmetic_precision_unconfirmed`. Final convergence additionally requires both complete residual enclosures inside their tolerances, both final search widths and both propagated temperature-error bounds. A finite high-magnitude cancellation fixture tests that floating-point zero residuals cannot fake convergence thousands of kelvins from the mathematical root. Overflow/nonfinite values produce a numeric-failure blocker and never enter JSON as NaN/Infinity.

A monotone outer residual proven not to cross zero within the validated domain produces an unsuitable state and `no_coupled_solution_in_validated_search_domain`. Endpoint signs use the residual enclosures propagated to the exact inner root; unresolved signs, missing brackets and iteration limits stay review_required. Missing evidence and convergence are separate from engineering release in every case.

## Analytical synthetic reference

Curve A is inherited from the D4A fixture, in kW:

`Q = 10 + 0.1 Te - 0.01 Tc`, `P = 2 + 0.01 Te`.

Evaporator medium: rho=1000 kg/m3, cp=4 kJ/(kg K), V=3.6 m3/h, inlet10 degC, epsilon=0.5. Thus C=4 kW/K and Ke=2 kW/K. These are explicitly synthetic values, not automatic water properties.

Air condenser: rho=1 kg/m3, cp=1 kJ/(kg K), V=5784 m3/h, inlet35 degC, epsilon=0.5, explicit SYNTHETIC-FAN/1500 rpm. Thus C=241/150 kW/K and Kc=241/300 kW/K.

Water condenser alternative: explicit synthetic liquid rho=1000, cp=4, V=1.446 m3/h, inlet35, epsilon=0.5. It deliberately produces the same C/Kc with a separate liquid-state contract and source-water loop.

The coupled linear equations are:

`2.1 Te - 0.01 Tc = 10`

`-0.11 Te + (241/300 + 0.01) Tc = 12 + (241/300)*35`.

Their independently known solution is **Te5/Tc50**, Q=10 kW, P=2.05 kW, required/synthetic condenser heat=12.05 kW. Evaporator outlet=7.5 degC, condenser outlet=42.5 degC. The gas/liquid heat balances agree independently through C*DeltaT.

## Security, compatibility and tests

The private service retains authenticated active accounts, persisted selectable tenants, legitimate Items owner/parent sharing, item view plus technicaldataset view. Synthetic reference additionally requires the existing item edit and technicaldataset import rights; technical view cannot invoke synthetic math. Site context, unknown users/owners and foreign dependency references are rejected. No new permissions or entitlements are created.

Every new run uses the D4A owner advisory lock and transaction, verifies the full dependency graph including inactive/shared/predecessor revisions, current identity/variant bindings, hashes, exact revisions and approval-chain evidence. Withdrawn or changed dependencies block all thermal iteration. New map/model types are always explicitly unreleasable, independently of draft status/provenance flags. Approved old records are not altered. Real-machine configurations and active data without explicit stored `synthetic_thermal_test_v1` / `production_import_allowed=false` provenance cannot produce a synthetic root.

Commands actually run:

```sh
php tests/items/thermal-circuit.php
php tests/items/compressor-polynomial.php
php tests/items/machine-stage.php
python3 tests/items/technical-data.py
php tests/security/shop-inquiry-calculation.php
php tests/security/inquiry-selection.php
```

The existing database runner creates only a temporary MariaDB with `--no-defaults --skip-networking`, dedicated /tmp socket/datadir and synthetic records. It still checks fresh installation, the real tagged 1.1.7 upgrade and partial/repeated targeted DDL. Negative corruption/revocation tests are confined to that disposable server. Synthetic packets cannot legitimately be approved; persisted revocation states are simulated directly only in the disposable negative fixtures. Official D2B/D4A approval/withdrawal lifecycle tests remain intact.

## Files and D4B2 prerequisites

Production changes: `TechnicalSchema.php`, `TechnicalJson.php`, `CompressorPolynomial.php`, `TechnicalDataset.php`, new `HeatExchangerMap.php` and `ThermalCircuit.php`. Tests: new `fixtures/thermal-circuit.php`, `thermal-circuit.php`, `thermal-circuit-db.php`, included by the existing `technical-data.php` runner. This report documents the fixed contract and numerical limits.

D4B1 intentionally blocks all multicircuit thermal solving, including physically independent circuits, until independence and all secondary boundary allocations have a validated coupling contract. Shared evaporators, condensers, air paths and liquid loops are not solved as unlimited independent resources. Water evaporator/condenser passages on the same secondary loop are also blocked. Multisection data can be represented but not thermally solved yet. D4A's multicircuit compressor aggregation is unchanged.

D4B2 needs authorized real OEM exchanger data and registered interpolation/validity contracts; consistent refrigerant saturation/superheat/subcooling definitions; proven compressor motor/casing heat balance; expansion/oil/parallel-stage/control evidence; real medium/property validity and pressure losses; air/fan or source-water boundary allocation; validated common-component coupling; and independent manufacturer/machine reference points. Nonrectangular domains and cases without a monotonicity certificate need a reviewed bounded numerical extension, not blind searching. D5 hydraulics/glycol and D6 heat recovery/heating remain separate.

No D4B1 SQL migration or manual database follow-up is required. No production data import, push, merge or deployment is performed. D4B2 is not started.
